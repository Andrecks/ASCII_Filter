# ASCII Shader — orientation notes for Claude

Real-time ASCII filter (WebGL2 fragment shader) shipped in three forms that share
ONE pipeline. PLAN.md is the source of truth: phase history, root causes, evidence,
open [ ] USER items. Keep maintaining it in the same style (checklists + measured
numbers + field-bug postmortems). This file is the fast map + the gotchas that are
NOT obvious from reading the code.

## Layout / data flow

- `proto/` — the shared engine and dev pages.
  - `ascii.js` — the renderer. Glyph atlas drawn with Canvas2D, auto-sorted by ink
    density → any charset becomes a luminance ramp; per-cell luminance sampled via
    mipmap `textureLod`; `uGain`/`uGamma` exposure uniforms (default 1 = neutral,
    only desktop passes them). `presets.js` charsets (ascii10/70, cyrillic, blocks).
  - `textlayer.js` + `domtext.js` — the "rotoscope": real DOM text re-drawn over
    the mosaic (NO OCR anywhere, rejected permanently). `cursor.js` ASCII cursor.
    `textgrid.js` frame→copyable chars. `forward.js` synthetic input (split mode).
  - Pages: `index.html`+`main.js` (Phase 0, draggable frame over fake `scene.js`),
    `live.html`+`live.js` (fullscreen "browser in a tab"), `article.html` (RU/EN
    demo). Run: `node server.js` → http://localhost:8137 (dependency-free; also
    launchable as "ascii-proto" from .claude/launch.json).
- `extension/` — Chrome MV3, current v0.2.1.
  - SOURCE = `extension/src/ext-main.js` + the proto modules. `extension/content.js`
    AND `proto/content.build.js` are both GENERATED by `node build-ext.js` (strips
    ES module syntax → one classic-script IIFE; the proto copy exists for dev-page
    smoke tests). Never hand-edit either. After editing any bundled proto module,
    rerun build-ext.js and bump the version (manifest.json + panel header) — users
    verify which build runs by that string after chrome://extensions Reload.
  - `bg.js` — worker: per-tab toggle badge, tabCapture streamId, auto-enable on
    navigation/opened tabs.
- `desktop/` — Electron overlay (Windows-only concerns live here).
  - `overlay.js` imports `../proto/*.js` directly (file:// ES modules, no bundling)
    → desktop/ MUST remain a sibling of proto/.
  - `main.js` — ALL policy: window flags, capture handler, tray, hotkeys, guard.

## Desktop: load-bearing and easy to break

- `disable-direct-composition` is CRITICAL (main.js top). With DCOMP on, Chromium
  windows carry WS_EX_NOREDIRECTIONBITMAP and SetWindowDisplayAffinity (content
  protection) SILENTLY fails → the overlay captures ITSELF → hall-of-mirrors decay
  to a black screen (the ETS2 field bug; measured GetWindowDisplayAffinity=0 while
  the API reported success). Env escapes: ASCII_KEEP_DCOMP=1, ASCII_SOFT=1
  (software rendering). If you ever touch window flags/capture, re-verify with
  --probe (below).
- Input passthrough is by construction, not by forwarding: `focusable:false`
  (WS_EX_NOACTIVATE — raises can never steal focus) + `setIgnoreMouseEvents(true)`.
  No OS-level text rotoscope (no DOM at OS level; OCR still rejected).
- Topmost guard (500ms): fullscreen apps join the topmost band and the LAST
  asserter wins → re-assert setAlwaysOnTop+moveTop+setContentProtection; restores
  if minimized/hidden; PAUSES while the tray menu is open (menu-will-show/close +
  tray right-click 8s fallback) or it would cover our own menu.
- Window is created `resizable:true`, then setBounds(display.bounds) +
  setResizable(false) in ready-to-show — Windows clamps non-resizable windows to
  the work area (symptom: 2560×1040 canvas, unfiltered 40px taskbar strip).
- `CalculateNativeWinOcclusion` disabled + `backgroundThrottling:false` — else
  Chromium marks the covered overlay occluded and freezes painting.
- Auto-exposure (overlay.js): 48×27 CPU downsample at 4 Hz → smoothed gain pulling
  scene avg toward 0.32 (1–10×), γ=0.6 in auto mode, user bias ×0.25–8. Night
  games average ~0.04 luminance — linear ramp alone maps everything to space.
- Capture auto-restarts on track `ended` and on display-metrics-changed (games
  switching display mode kill the track); window re-fitted to new bounds.
- Hotkeys: Ctrl+Alt+A toggle, ↑/↓ cell size, ←/→ brightness bias, D debug line
  (video size / avg+max lum / gain / fps / track state / restarts), X quit.

## Run & verify (desktop)

- Run: `desktop\start.cmd`. The machine's global npx shim is BROKEN — never
  `npx electron`; always the local `node_modules\electron\dist\electron.exe`.
  If electron.exe is missing after npm install: `node node_modules/electron/install.js`.
- `--windowed` = small resizable window (dev). `--selftest` = windowed 60-frame
  run → selftest.json/.png. Expect ok:true, fps well over 60.
- `--probe` = REAL fullscreen evidence run (~5 s, auto-quits) → probe.json +
  probe.png (ASCII output) + probe-video.png (RAW captured frame = what capture
  actually sees). probe.json self-diagnoses feedback: `selfCaptureSuspected`
  (green-dominant + dark ⇒ capturing our own green-on-black output). After any
  window/capture change: run probe AND view probe-video.png — it must show the
  real desktop, NEVER a green glyph field.
- Selftest/probe artifacts are gitignored — regenerate, don't commit.

## Testing conventions

- Headless verification happens in the embedded browser pane against the demo
  source / article.html. Anything needing a real "Share" click or a real game is a
  USER manual test — leave it as an unchecked `[ ] USER:` item in PLAN.md with
  exact steps, and ask the user to run it.
- When a field bug arrives as a screenshot: reproduce the coordinate/luminance
  math before guessing (Phase 3.3/3.4/5 postmortems in PLAN.md are the pattern:
  make it observable first — debug readouts, probe dumps — then fix).
